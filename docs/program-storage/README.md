# Program Storage

Статус: реализовано.

Этот каталог описывает постоянное хранение программ Swing Metro во flash через
LittleFS. Пользователь видит 16 программных ячеек (`0`–`15`). Дополнительно
существует скрытая системная ячейка `16` — `Current Program`: она восстанавливает
рабочее состояние после включения питания.

## Согласованное поведение

- Программа содержит tempo, swing, volume, настройки MIDI Clock и все параметры
  16 шагов. В первой версии шаг хранит `enabled`, `note`, `velocity`; формат
  заранее допускает последующие параметры, такие как gate и повторения.
- Долгое нажатие ручки Volume немедленно отправляет Note Off, останавливает
  локальный транспорт и открывает модальное окно `Save / Load`.
- Пока открыто это окно, секвенсор не реагирует на локальные или внешние
  транспортные события. После закрытия он остаётся остановленным; для External
  MIDI Clock нужен следующий `Start`.
- Поворот ручки Volume выбирает действие и затем ячейку, короткое нажатие
  подтверждает выбор.
- `Save` сохраняет рабочую программу в выбранную пользовательскую ячейку.
  `Load` загружает выбранную пользовательскую ячейку в рабочее состояние.
  Успешные Save и Load обновляют `Current Program`.
- Изменённая рабочая программа автоматически записывается в `Current Program`,
  но только при остановленном транспорте и только если CRC canonical payload изменилась.

Запись или чтение flash во время воспроизведения запрещены. Операции flash могут
приостановить второе ядро RP2350 и нарушить MIDI-тайминг; перенос вызова на UI-ядро
не отменяет это ограничение.

## Формат и совместимость

Каждый образ программы имеет неизменяемый заголовок: magic, версия контейнера,
номер ревизии, длина payload и CRC. Payload состоит из полей
`тип → длина → данные`. Читатель:

- пропускает неизвестные поля;
- подставляет defaults для отсутствующих известных полей;
- отклоняет повреждённые или несовместимые данные;
- после следующего сохранения записывает актуальный формат.

Каждая логическая ячейка хранится в двух чередующихся физических копиях A/B с
монотонной ревизией и CRC. При загрузке выбирается новая валидная копия. Это
сохраняет прежнюю версию при выключении питания во время записи.

## Общие ограничения

- C++17; без динамического выделения памяти в рабочем пути.
- Codec и политика выбора копии тестируются в native-среде; вызовы LittleFS
  изолированы за адаптером.
- UI получает только snapshot через `UiViewModel`; прямой доступ к LVGL из
  основного ядра запрещён.
- Любая операция Save/Load сначала гасит активную ноту и останавливает транспорт.
- Пустой LittleFS-раздел первично форматируется только текущей mount-инициализацией;
  отдельного auto-format пути во время Save/Load/autosave нет.
- После каждого меняющего код этапа: `make format` и `make verify`.
