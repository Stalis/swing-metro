# Архитектура драм-машины

Статус: согласованный план v1. Документ описывает целевое устройство, а не уже
реализованные возможности. Изменения прошивки выполняются отдельными этапами.

## Объём v1

| Область | Решение |
| --- | --- |
| Плата | Raspberry Pi Pico 2 W |
| Среда | PlatformIO, Arduino core Earle Philhower |
| Звук | Сэмплер: сначала один встроенный сэмпл, затем небольшой встроенный набор |
| Голоса | Небольшой фиксированный пул, перекрытие хвостов разрешено |
| Секвенсор | Один трек, 16 шагов |
| Ввод | Матрица кнопок 4×4 и три энкодера с кнопками |
| Экран | ST7735, существующая Arduino_GFX |
| Groove | Общий для паттерна: Straight, MPC-style, Custom preset |
| USB MIDI | Приём нот, отправка нот секвенсора, внешний MIDI Clock и транспорт |
| USB Audio | Один выходной аудиопоток из устройства в компьютер |
| Clock | Явный выбор Internal или USB MIDI |
| Хранение | Сэмплы и начальные groove-пресеты встроены в прошивку |

Один трек не означает один голос: новый удар может звучать одновременно с хвостом
предыдущего. Choke в v1 не реализуется.

Частоту дискретизации, разрядность, число каналов USB Audio, размер пула голосов
и поведение при его заполнении определяем при проверке аудиотракта. Один трек
секвенсора не задаёт число каналов аудиопотока.

## Исходное состояние

На момент согласования в проекте есть драйверы матрицы и энкодеров, числовые
параметры Tempo/Swing/Volume и их отображение на ST7735. Музыкальный секвенсор,
аудиодвижок и composite USB MIDI + Audio ещё предстоит реализовать.

В `platformio.ini` указан `rpipico2`. При реализации необходимо проверить поддержку
Pico 2 W установленной платформой и выбрать соответствующий board ID. Wi-Fi в v1
не включается.

Перед расширением ввода необходимо исправить доставку событий между IRQ и основным
циклом, согласовать нумерацию кнопок, подключить обработку кнопок энкодеров и
проверить схему матрицы для одновременных нажатий. Прямой доступ двух ядер к общим
изменяемым параметрам нужно заменить согласованной передачей состояния.

```text
lib/

    library.json
    src/
      ButtonMatrix.h / .cpp
      ButtonState.h / .cpp
  Encoder/
    library.json
    src/
      Encoder.h / .cpp

src/

  app.h / .cpp                 # действия пользователя и связывание модулей
  board_config.h               # пины и настройки конкретной сборки

  sequencer/
    pattern.h                  # паттерн из 16 шагов
    transport.h / .cpp         # источник clock, tempo, транспорт, позиция
    midi_clock.h / .cpp        # оценка внешнего tempo и фазы, потеря clock
    sequencer.h / .cpp         # расписание событий

  audio/

    usb_midi.h / .cpp          # приём и передача MIDI
    usb_audio.h / .cpp         # передача PCM в компьютер

  ui/
    display.h / .cpp           # настройка Arduino_GFX и ST7735
    main_screen.h / .cpp       # GUI драм-машины

  presets/
    groove_presets.h           # встроенные custom groove-пресеты
  utils/

assets/
  samples/                     # исходные сэмплы для подготовки прошивки

test/
  test_native/
    ...                        # существующие проверки
    sequencer/                 # timing, groove и внешний clock
    audio/                     # границы сэмпла и повторный запуск

docs/
  architecture.md
  hardware.md                  # добавляется при фиксации подключений
```

Это целевая структура: файлы добавляются по мере реализации, без пустых модулей
заранее. Определения шаблона `ButtonMatrix` должны быть доступны из заголовка
(при необходимости через включаемый файл реализации), чтобы другие размеры матрицы
не требовали проектного генератора или заранее заданных инстанцирований.

### Граница lib/ и src/

В `lib/` находятся универсальные самописные драйверы, переносимые в другой проект
без копирования файлов из `src/`.

- Пины и параметры передаются снаружи; разводка платы не зашита в библиотеку.
- Нет зависимостей от приложения, GUI, паттерна, tempo и глобальных объектов проекта.
- Зависимости и поддерживаемые платформы указаны в `library.json`.
- Зависимость от Arduino допустима; универсальность не означает работу без Arduino.
- Документируются debounce, допустимый контекст вызовов и потокобезопасность.
- `ButtonState` остаётся частью `ButtonMatrix`, без отдельной библиотеки.

Настройка готовой Arduino_GFX под конкретный ST7735 остаётся в `src/ui/`: это
аппаратная привязка приложения, а не новый универсальный драйвер. Вспомогательные
утилиты не превращаются автоматически в самостоятельные библиотеки.

## Данные и ответственность

| Данные или модуль | Ответственность |
| --- | --- |
| Step | Включён ли шаг, velocity |
| Pattern | 16 шагов, назначенный сэмпл, параметры MIDI и groove |
| Transport | Источник clock, tempo, play/stop, музыкальная позиция |
| GroovePreset | Имя и 16 знаковых временных смещений |
| UiState | Страница, выбранный параметр и состояние редактирования |
| Sequencer | Преобразование паттерна и groove в события с точным временем |
| SamplePlayer | Запуск голосов и рендер аудио, без зависимости от USB и GUI |

Матрица редактирует 16 шагов единственного трека. Позиция воспроизведения и состояние
GUI не являются данными сохраняемого паттерна. Массив из 16 неиспользуемых треков
и универсальная система проектов в v1 не создаются.

`sequencer/` не зависит от Arduino, GPIO, экрана и USB. Его время и логику можно
проверять native-тестами на компьютере.

## Поток событий

```text
Матрица / энкодеры -> App -> Pattern / Transport / Groove
                                      |
                                  Sequencer
                                      |
                           события с точным временем
                              /               \
                        SamplePlayer        USB MIDI OUT
                             ^
USB MIDI Note On ------------|
                             |
                         USB Audio -> компьютер

USB MIDI Clock / transport -> MidiClock / Transport
Снимок состояния и позиции -> GUI
```

- Входящие ноты и секвенсор используют один проигрыватель сэмпла.
- Секвенсор заранее назначает позицию удара в аудиопотоке.
- Live MIDI запускается в ближайшей доступной позиции с минимальной задержкой.
- Groove применяется к секвенсору, но не задерживает и не квантует live MIDI.
- Входящие ноты по умолчанию не пересылаются обратно в MIDI OUT.
- Ноты секвенсора отправляются наружу с корректными Note Off.
- Live MIDI работает независимо от состояния транспорта секвенсора.

## Музыкальное время и groove

Музыкальные позиции переводятся в номера аудиосэмплов. Удар запускается с нужным
смещением внутри PCM-блока, а не только на его границе. Дробная часть длительности
шага сохраняется, чтобы округление не накапливало дрейф.

Внутренний звук и исходящие MIDI-ноты используют одно расписание. Фактическое время
доставки MIDI компьютеру дополнительно зависит от USB и хоста.

### MPC-style

Для шестнадцатых процент swing задаёт положение второго удара внутри пары:

```text
D = длительность прямой шестнадцатой
s = swing / 100

первый удар:              0
второй удар:              2 * D * s
начало следующей пары:   2 * D
```

- 50% даёт прямые шестнадцатые.
- Примерно 66.67% даёт отношение длительностей 2:1.
- Длительность пары и такта не изменяется.

Это MPC-style, а не эмуляция временной сетки конкретной модели MPC. Текущий
UI-диапазон 50–100 нельзя переносить без изменения: при 100% второй удар совпадает
с началом следующей пары. Рабочий диапазон фиксируется при реализации.

### Custom preset

Пресет содержит 16 знаковых смещений относительно прямой сетки, выраженных в долях
шага или музыкальных тиках, не в миллисекундах. Характер groove сохраняется при
смене tempo. Предусматриваются выбор пресета и глубина его применения.

Straight, MPC и Custom являются альтернативными режимами; наложения MPC и Custom
в v1 нет. Для отрицательных смещений события рассчитываются заранее, включая
границу паттерна. Допустимые смещения, пересечения событий и поведение отрицательного
смещения при старте должны быть определены и покрыты тестами до завершения модуля.

## Внешний USB MIDI Clock

Источники Internal и USB MIDI выбираются явно, без автоматического переключения.
`usb_midi` передаёт сообщения с отметками времени получения; `midi_clock` оценивает
tempo и фазу независимо от USB-стека.

| Сообщение или состояние | Поведение в режиме USB MIDI |
| --- | --- |
| Clock | 24 импульса на четверть, уточнение tempo и музыкальной фазы |
| Start | Запуск с начала паттерна |
| Stop | Остановка секвенсора без принудительного обрыва аудиохвостов |
| Continue | Продолжение с сохранённой позиции |
| Song Position Pointer | Установка позиции, для текущего паттерна по модулю 16 шагов |
| Потеря clock | По тайм-ауту остановка секвенсора и статус Clock lost |

При потере clock нет перехода на внутренний tempo. Значение тайм-аута и восстановление
после потери синхронизации уточняются при реализации. Внешний tempo отображается
на экране, но не изменяется энкодером.

На прямую шестнадцатую приходится шесть MIDI Clock. Swing-события могут находиться
между импульсами, поэтому нужна интерполяция с учётом джиттера. Коррекция фазы не
должна повторно запускать уже сыгранные события.

Clock задаёт музыкальную позицию, а не частоту аудио: смена tempo не меняет скорость
проигрывания или высоту сэмпла. Swing применяется к нотам, а не к MIDI Clock.
Передача собственного MIDI Clock наружу не входит в согласованный обязательный
объём v1.

## Аудио, выполнение и GUI

Для первого сквозного запуска используется подготовленный на компьютере PCM-сэмпл,
включённый в прошивку. Парсер WAV на устройстве, файловая система и универсальный
поставщик сэмплов пока не нужны.

Совместная работа USB MIDI и USB Audio на выбранном core должна быть проверена
ранним прототипом. Наличие низкоуровневого audio class в стеке само по себе не
подтверждает работоспособность нужного composite-устройства.

- Реальное время отделяется от GUI и операций хранения.
- Для изменяемого состояния определяется один владелец; команды передаются
  ограниченной очередью, GUI получает согласованный снимок.
- Текущий `RoundBuffer` не считается готовой межъядерной очередью.
- В аудиокритическом пути нет динамического выделения памяти, записи flash,
  логирования и отрисовки.
- GUI обновляет изменившиеся области с ограничением частоты; начальный ориентир
  составляет 30 кадров в секунду.
- Второе ядро под GUI является первоначальным вариантом, а не жёстким ограничением.
  Распределение задач определяется после проверки USB-стека и нагрузки.

GUI показывает шаги, позицию воспроизведения, транспорт, tempo, groove, громкость,
источник clock и статус синхронизации. Для v1 достаточно Arduino_GFX; RTOS, LVGL
и универсальная шина событий заранее не вводятся.

## Этапы реализации и проверки

1. **Библиотеки и плата.** Выделить ButtonMatrix и Encoder в `lib/`, исправить ввод,
   проверить мультинажатия и конфигурацию Pico 2 W.
2. **Сквозной USB-аудиотракт.** Входящая MIDI-нота запускает встроенный сэмпл,
   повторные удары перекрываются, компьютер получает непрерывный USB Audio.
3. **Внутренний секвенсор.** Реализовать 16 шагов, транспорт, tempo, MPC/custom
   groove и отправку MIDI-нот с Note Off.
4. **Внешняя синхронизация.** Реализовать USB MIDI Clock, Start/Stop/Continue,
   Song Position Pointer, интерполяцию и обработку потери clock.
5. **GUI.** Подключить редактирование шагов, параметры, выбор источника clock
   и отображение состояния через безопасную передачу данных.
6. **Нагрузочная проверка.** Проверить одновременную работу MIDI, аудио, ввода
   и экрана, смену tempo/groove, заполнение пула голосов и отключение USB.

Используем существующую native/Unity инфраструктуру. Проверяем длительность такта,
отсутствие накопленного дрейфа, границы паттерна, отрицательные смещения, границы
PCM-данных и повторные удары. Внешний clock тестируем с искусственным джиттером,
изменением tempo и коррекцией фазы без двойных ударов. На железе проверяем
синхронизацию с DAW и отсутствие аудиопровалов под нагрузкой GUI.

## За пределами v1

- Загрузка сэмплов по Wi-Fi.
- SD-карта, система проектов и сохраняемых пресетов.
- Расширение до 16 треков.
- Настраиваемый choke.
- Локальный аудиовыход, например через I2S/DAC.

Загрузка сэмплов по Wi-Fi и OTA-обновление прошивки являются разными операциями.
Запись во внутреннюю flash может мешать исполнению кода и чтению сэмплов, поэтому
первоначальный режим загрузки предполагает остановленное воспроизведение.
Разметка flash под загружаемые данные определяется при реализации этой функции;
в v1 отдельные подсистемы под будущие возможности не создаются.
