# Tick Transport и фазовый MIDI-планировщик

Статус: запланировано.

Этот каталог описывает замену текущего планирования по `micros()` на единый
музыкальный transport, основанный на MIDI Clock ticks. Цель — отправлять clock и
ноты в определённом порядке у одной границы тика, поддерживать внутренний и
внешний источник одинаковым способом и подготовить основу для swing.

## Итоговый контракт

- Музыкальная позиция хранится как монотонный `TransportTick`; один tick равен
  одному MIDI Clock импульсу (`24 PPQN`). Одна текущая шестнадцатая — шесть ticks.
- `Sequencer` не сравнивает абсолютные микросекунды и не владеет периодом шага.
  Он продвигается только командой transport на заданном количестве ticks.
- MIDI-событие назначается на пару `(tick, phase)`. `phase` — безразмерная доля
  интервала от текущего tick до следующего, а не число миллисекунд.
- `phase = 0` означает границу tick. Для представления используется `uint16_t`:
  `0` — 0%, `32768` — 50%, `49152` — 75%; максимальное значение обозначает
  момент непосредственно перед следующим tick. Float в рабочем пути не нужен.
- На границе tick outgoing `0xF8` отправляется перед MIDI-событиями с `phase = 0`.
  События с ненулевой фазой отправляются по deadline, рассчитанному из актуального
  периода, в устойчивом порядке очереди.
- BPM и `micros()` остаются физическим способом породить tick или deadline, но не
  являются моделью музыкской позиции. При смене BPM будущие phase-события сохраняют
  свою относительную долю нового интервала.

## Согласованная семантика источников

| Режим | Кто создаёт tick | Период | Outgoing clock |
| --- | --- | --- | --- |
| `Off` | Internal tick source | Установленный BPM | Нет |
| `Internal` | Internal tick source | Установленный BPM | Да, `0xF8` на каждой границе |
| `External` | Принятый `0xF8` | Сглаженная оценка входящих интервалов | Нет |

`Start`, `Continue` и `Stop` меняют состояние транспорта. Внешний `0xF8` при
остановленном транспорте может обновлять lock/tempo, но не продвигает секвенсор.
При потере external clock transport останавливается; скрытого перехода на internal
tempo нет.

## Отправная точка и заменяемые правила

Сейчас `Sequencer::update(micros())` самостоятельно определяет границу шага;
`MidiClockTransmitter` отдельно догоняет `0xF8`; `processMidiStepBoundary()`
отправляет ноты напрямую. В `ExternalMidiClock` уже есть счётчик шести входящих
ticks на шаг. Эти три механизма должны быть сведены к одному transport-потоку.

Этот план заменяет для нового пути порядок из старого
`docs/midi-clock/03-internal-midi-clock.md`: на одной границе сначала outgoing
`0xF8`, затем Note Off, затем Note On. Старый документ остаётся историческим
планом внедрения MIDI Clock; его нельзя использовать как спецификацию порядка
пакетов после этой миграции.

## Общие ограничения

- C++17; в аудио/transport-пути нет динамической памяти, `std::vector`,
  `std::function`, доступа к LittleFS, логирования или LVGL.
- Очередь имеет фиксированную вместимость. Базовый бюджет — восемь MIDI-пакетов
  на один tick; переполнение является наблюдаемой и тестируемой ошибкой, не тихой
  перезаписью события.
- Состоянием транспорта владеет основное ядро. IRQ или USB receive path только
  публикуют входящий tick/событие через безопасный маленький интерфейс; они не
  вызывают USB MIDI write и не обращаются к секвенсору.
- Все wraparound-сравнения `micros()` используют unsigned subtraction. Счётчик
  музыкских ticks должен быть достаточно широким, чтобы не переполняться в
  реалистичном времени работы (`uint64_t` предпочтителен).
- Изменения UI и сохранённого BPM не должны менять LVGL из основного ядра и не
  должны писать flash во время работающего транспорта.

## Общая приёмка

Каждый кодовый этап завершается `make format` и `make verify`. Native-тесты
покрывают порядок пакетов, переполнение очереди, фазу 0/50/75%, смену BPM,
изменение external period, Start/Stop/Continue, loss/relock и wraparound.
На устройстве проверить MIDI monitor/DAW минимум на 40, 120 и 240 BPM, длительную
работу, смену темпа в движении, swing и внешний master с джиттером.
