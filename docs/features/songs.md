# Songs — planned

A saved `Program` is separate from a `Song`. A `ProgramId` is stable for a user slot 0–15; the current autosave slot 16 is not a song target. Saving a new program in slot N updates what future references to N resolve to. A song is a bounded, ordered list of `{ProgramId, repetitions}` values; one repetition is one full cycle of the referenced program's current length. Zero repetitions and invalid IDs are rejected.

Example: `P0×2 → P3×1 → P2×4 → P1×1 → P0×2`. It contains five entries and ten program cycles. At 16 steps per program this is 160 steps; with variable lengths it is the sum of `length(program) × repetitions` for each entry. Repeated references do not copy program data in the saved song.

Before Play, resolve every reference, verify program image version/CRC and fields, and preload all required programs and the song into RAM. A missing, deleted or corrupt referenced program blocks song start with the failing entry and ID shown; silently skipping it would change musical structure. Define deletion semantics before adding a delete command: either reject deletion while referenced or leave a broken reference that is diagnosed before Play. Never silently retarget IDs. Existing slot overwrite keeps the ID and affects a future run; an already running song uses a captured revision/snapshot until its session ends.

Keep editing and persistence distinct from execution. A song editor changes an in-memory draft; a versioned song codec/store saves stable IDs and repetition counts while transport is stopped. A `SongCursor` owns entry index, remaining repetitions and cycle progress; it is playback state, not part of the saved `Song`. A transition occurs at the program cycle boundary without resetting master MIDI Clock. The next program must already be in RAM. Proposed first-release policy: Stop at song end, no automatic loop; edits apply on a later run, not during playback. `Continue` after Stop or loss needs an explicit cursor policy before implementation.

Program storage currently uses v1 A/B images with CRC and one current autosave slot. Add a separately versioned song container and migration rules; import v1 programs as length 16, one-shot, repeat 1 and MIDI channel value 0 (user channel 1), and write the new format only on an intentional stopped save. The song store must not reuse the current-program autosave as 16 competing track states. No LittleFS access occurs between Play and a safe stopped state.

Acceptance: the exact example above, lengths 1/3/16, minimum/maximum repetition validation, repeated IDs, overwrite and missing/corrupt references, transition with no duplicate attack or gap, Stop/restart/Continue policy, persistence round trip and power-cycle restore, and a storage spy proving no flash I/O during playback.
