# Этап 8. Интеграция матрицы кнопок

Статус: запланировано.

## Задача для агента

Подключить 16 кнопок шагов через Button adapter и контекстный стек. Короткое
нажатие переключает шаг, длительное возвращает смысловое событие открытия настроек
конкретного шага. Реальную LVGL-навигацию оставить этапу 9.

## Предусловия и чтение

- Прочитать `00-introduction.md` и этот документ.
- Прочитать передачи результата этапов 1–7.
- Изучить актуальные:
  - `lib/ButtonMatrix/src/button_matrix.h` и `.ipp`;
  - `lib/ButtonMatrix/src/button_state.h` и `.cpp`;

  - `docs/hardware.md`.

## Существующая нумерация

Матрица 4x4 использует compile-time отображение `PadButtonIds`:

```text
0  1  8  9
2  3 10 11
4  5 12 13
6  7 14 15
```

Логический ID от `getButtonId()` должен сохраниться. Не заменять его физическим
индексом и не менять разводку или алгоритм сканирования.

## Расширение ButtonMatrix

Текущий публичный интерфейс сообщает событие первого нажатия, но для long press
нужны оба края. Добавить запросы с семантикой существующего `ButtonState`:

```cpp
isButtonJustPressed(...)
isButtonHolding(...)
isButtonJustReleased(...)
isButtonReleased(...)
```

Поддержать координатную и линейную формы, если обе реально нужны интеграции.
Существующий `isButtonPressed()` сохранить как совместимый alias для just pressed,
если удаление потребовало бы несвязанного изменения API.

Не менять debounce, порядок `readButtons() -> consume events -> update()` или
электрическую логику матрицы.

## Фиксированное хранилище адаптеров

Создать ровно 16 `ButtonInputAdapter`, размещённых в `std::array`. Каждый объект
получает логический SourceId соответствующего шага. Никакого выделения объектов при
нажатии или в основном цикле.

После `readButtons()` приложение для каждой кнопки:

1. Передаёт just-pressed edge в `onPressed(now)`.
2. Пока кнопка удерживается, вызывает `update(now)` для long press.
3. Передаёт just-released edge в `onReleased(now)`.
4. Каждый элемент возвращённого fixed batch отправляет в `contextInput.dispatch()`.
5. Полученный AppEvent обрабатывается только после возврата dispatch.
6. После обхода вызывается существующий `buttonMatrix.update()`.

## Смысловые события

Расширить app-level `InputId` и `AppEvent`, не меняя универсальные типы библиотеки:

```cpp
struct ToggleStep {
    uint8_t step;
};

struct OpenStepSettings {
    uint8_t step;
};
```

`MainDisplayContext` преобразует:

```text
Step N + ButtonPhase::Clicked     -> ToggleStep{N}
Step N + ButtonPhase::LongPressed -> OpenStepSettings{N}
```

`Pressed` и `Released` могут вернуть pass, если для них пока нет действия.

Короткое нажатие больше не должно вызывать `toggleStep()` непосредственно в момент
just pressed. Оно выполняется только после `Clicked`, то есть при отпускании.

## Обработка AppEvent

- `ToggleStep{N}` вызывает существующий `mainSequencer.toggleStep(N)`.
- `OpenStepSettings{N}` на этом этапе сохраняется/наблюдается как событие и может
  обновить app-level выбранный шаг, но фактический экран и `StepSettingsContext`
  подключаются в этапе 9.
- Если позднее контекст будет добавляться по событию этой кнопки, оставшиеся фазы
  того же удержания нельзя передавать новому контексту как независимое действие.
  Правило изоляции жеста и тесты описаны в `09-application-ui-coordination.md`;
  здесь новый экран ещё не активируется.
- Проверить диапазон `N < 16` на границе приложения. Невалидный внешний ID не должен
  обращаться за границы секвенсора.

## Тесты

- Все 16 logical IDs сохраняют текущую раскладку.
- Click каждого шага создаёт `ToggleStep` с правильным номером.
- LongPressed создаёт `OpenStepSettings` с правильным номером.
- LongPressed не создаёт ToggleStep ни до, ни после release.
- Две одновременно удерживаемые кнопки имеют независимые таймеры.
- Одновременный click двух кнопок создаёт два последовательных входных события.
- Необработанные Pressed/Released безопасно проходят или исчезают.
- Существующие тесты ButtonState/ButtonMatrix, если есть, продолжают проходить.
- Firmware build подтверждает шаблон `ButtonMatrix<4, 4, PadButtonIds>`.

Аппаратно повторить одиночные, быстрые, длительные и одновременные нажатия. Известное
ограничение резкого отпускания нескольких кнопок из `docs/hardware.md` не исправлять
в рамках этого этапа без отдельного согласования.

## Критерии готовности

- В `main.cpp` нет прямого `toggleStep()` по just-pressed матрицы.
- Click и LongPressed взаимоисключающие.
- Нумерация 0–15 не изменилась.
- Матрица не знает о контекстах или AppEvent.
- Все объекты и временные batches имеют фиксированную ёмкость.

## Передача результата

Зафиксировать добавленные запросы ButtonMatrix, long-press threshold, расположение
16 адаптеров, расширения InputId/AppEvent и результаты автоматических/аппаратных
проверок. Этап 9 использует точное событие `OpenStepSettings`.
