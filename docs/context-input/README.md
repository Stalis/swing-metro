# Context Input

Статус: согласованный план, этапы 1–6 выполнены.

Этот каталог описывает универсальную систему контекстного ввода для Swing Metro.
Документы разбиты так, чтобы каждый этап можно было передать отдельному агенту без
пересказа исходной беседы.

## Как работать с документами

Перед началом любого этапа агент должен:

1. Прочитать [00-introduction.md](00-introduction.md).
2. Прочитать документ назначенного этапа целиком.
3. Проверить актуальное состояние репозитория и результаты предыдущих этапов.
4. Не реализовывать последующие этапы и не расширять согласованный объём молча.
5. После реализации обновить в своём документе статус и секцию `Передача результата`:
   перечислить фактический API, изменённые файлы, проверки и отклонения от плана.

Документы этапов самодостаточны по постановке задачи, но выполняются последовательно:

## Общие команды проверки

После этапов, меняющих код, выполняются как минимум:

```sh
make format
make verify
```

`make format` изменяет только C/C++-файлы в `src`, `include`, `lib` и `test`.
`make verify` не меняет форматирование: он проверяет его, запускает `clang-tidy`,
native-тесты и сборку прошивки. Отдельные цели и требуемые инструменты перечислены
командой `make help`.

`pio check` не входит в обязательную проверку: текущая конфигурация запускает
clang-tidy с `--fix` и может изменять файлы.

## Граница этого плана

План касается маршрутизации пользовательского ввода. Он не проектирует аудиодвижок,
MIDI, музыкальный clock или новый UI. Такие изменения допустимы только в той мере,
в какой они необходимы для подключения уже согласованных смысловых событий.
