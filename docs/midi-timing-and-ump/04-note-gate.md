# Этап 4. Gate Percent для ноты

Статус: запланировано. Зависит от этапов 1–3.

## Цель

Добавить редактируемую и сохраняемую длительность каждой ноты. Планировать
Note Off независимо от следующего Note On, включая deadline между MIDI Clock.
Это завершает управление note/velocity/gate в редакторе шага и расширяет нагрузку
на планировщик перед этапом 5. Полная полифония/MPE сюда не входят.

## Предлагаемый контракт

Следующие значения и правила — проектные решения этого плана, а не ранее
заданные пользователем параметры:

- Gate Percent хранится на каждом шаге: целое 1–100%, значение по умолчанию 100%.
  0% не используется для mute: у шага уже есть enabled.
- База длительности — прямая шестнадцатая, то есть шесть Clock ticks.
  Запрошенная длительность = `6 ticks * gatePercent / 100`.
- Начало длительности — назначенная позиция Note On с учётом swing, а не момент
  успешного USB retry. Задержка отправки не должна растягивать музыкальное время.
- По указанию пользователя режим по умолчанию monophonic: предыдущая нота
  завершается следующей только при перекрытии. Собственный deadline равен
  `off = on + duration`; ограничивать его прямой границей шага нельзя.
- Перед новым Note On завершить предыдущую ещё активную ноту. Если её Gate уже
  истёк, дополнительный Note Off не отправлять. Выключенный шаг не запускает
  новую ноту и сам по себе не обрывает предыдущую.
- Gate 100% означает длительность одной прямой шестнадцатой от начала ноты.
  При swing нота может пересечь прямую границу шага; если следующий Note On
  наступает раньше её Off, она завершается перед этим On. Это явно меняет
  прежнее безусловное завершение на каждой прямой границе.
- Gate не сдвигает Clock, Note On и формулу swing. Tie не добавляется.
- Пример: 120 BPM, swing 50, шаг 125 мс, Gate 50% → Note Off через 62,5 мс.
  Для swing пример вычислять через существующую `swingPhase`, не подменять её
  другой музыкальной формулой в рамках этой задачи.
- Запланированная пара On/Off фиксирует note, gate и порядок при её создании.
  Редактирование действует для ещё не запланированных нот; текущая нота не
  получает новое значение. Изменение BPM меняет физическое время оставшейся
  музыкальной длительности; External использует актуальную оценку периода.

## Работа

1. Добавить gate в `SequencerStep`, `ProgramStep`, валидацию, capture/apply,
   сохранение пользовательских слотов и текущей программы.
2. Расширить кодек совместимым полем: старые программы без Gate получают 100%.
   Не менять длину существующего step-поля без механизма совместимости. Проверить
   размеры буферов, CRC, обе копии хранения и ошибки/некорректные значения нового поля.
3. Планировать связанные On/Off через события этапа 2. Fractional tick переносится
   в следующую tick-позицию корректно; определить округление и погрешность phase.
   Note Off должен быть запланирован и после последнего шага перед переходом такта.
4. Пересчитать ёмкость очереди и квоты с учётом обоих событий и lookahead. События
   могут иметь несколько независимых deadline, не только границы шестнадцатых.
5. Убрать прежний безусловный Off на следующей прямой границе шага.
   На совпавшем deadline сохранять Clock → Note Off → Note On. Для одинакового
   pitch старая завершающая команда не должна обрывать новую ноту. При досрочном
   завершении из-за нового On отменить/инвалидировать старый Gate Off по идентичности
   запуска ноты, а не только pitch. Учесть как очередь расписания, так и pending retry.
   Логическое действие замены ноты сохраняет порядок Off → On при backpressure.
6. Согласовать с backpressure: если Note On не принят до истечения gate, не
   воспроизводить его позднее как новую ноту. Если принят — обеспечить обработку
   соответствующего Off согласно политике этапа 2. Stop/loss/mode switch очищают
   будущие события и завершают принятую ноту без дублирования.
7. Добавить `AdjustGate` и редактирование в Step Settings свободным там
   VolumeEncoder (сейчас событие consume без действия). Основной экран сохраняет
   управление Volume. Проверить приоритеты Shift и модальных контекстов.
8. Добавить Gate в UI-снимок, отображение выбранного шага и проверки согласованности
   межъядерной публикации. Подготовить короткое описание управления пользователю.

## Проверки и критерии готовности

- Native: 1/25/50/75/100%, граничные/недопустимые значения; разные gate соседних
  шагов; enabled/disabled; swing 50/90; дробный deadline между Clock; переход такта.
- Monophonic: неперекрывающиеся ноты, перекрытие при swing, пустой следующий шаг,
  совпадение gate deadline с новым On, одинаковый pitch и запоздалый Off старого
  запуска. Переход прямой границы сам по себе не завершает ноту.
- Проверить отдельные Off, отсутствие дублей, одинаковую ноту в соседних шагах,
  Stop до/после gate, смену режима, loss, retries и просроченный Note On.
- Проверить редактирование уже звучащей/запланированной и будущей ноты, изменение
  BPM и external периода; Gate не меняет сетку Clock.
- Программы без поля Gate загружаются с 100%; новые значения переживают save/load
  и восстановление текущей программы; CRC/повреждение и обе копии проверены.
- UI показывает Gate выбранного шага; редактирование не меняет глобальную громкость.
- На устройстве и хосте сравнить назначенные/наблюдаемые On/Off при нескольких
  gate. Принимающий инструмент может игнорировать Note Off (например, one-shot
  ударный звук), поэтому слуховой тест не заменяет проверку MIDI-событий.
- Выполнен `make verify`; изменения схемы программы и контракта редактора описаны.

## Нагрузка и границы

Gate обычно сохраняет два сообщения на ноту. Он увеличивает число различных
моментов обслуживания и проверяет независимое завершение нот, но не гарантирует
увеличения USB-трафика. Для проверки большого потока контроллеров по-прежнему
нужен отдельный генератор этапа 5. Одновременное звучание нескольких нот, Gate >100%, tie,
MPE и переход на UMP остаются вне этого этапа.
