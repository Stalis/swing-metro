# Этап 4. Входящий External MIDI Clock

Статус: запланировано. Зависит от этапов 1–3.

## Задача

В режиме `External` принимать USB MIDI real-time Clock и transport, подчинять им
секвенсор и отображать фактический статус синхронизации. В `Off` и `Internal`
входящие clock-сообщения не должны менять темп, фазу или transport устройства.

## Согласованный протокол

| MIDI сообщение | Действие в `External` |
| --- | --- |
| `0xF8` Clock | 24 импульса на четверть; обновляет оценку периода/tempo и музыкальную фазу. Шесть импульсов соответствуют одной прямой шестнадцатой. |
| `0xFA` Start | Сбросить позицию к началу паттерна и запустить ожидание/обработку external clock. |
| `0xFC` Stop | Остановить секвенсор; закрыть активную MIDI-ноту по существующему правилу. |
| `0xFB` Continue | Продолжить с сохранённой позицией. |
| `0xF2` Song Position Pointer | Поддержать, если TinyUSB надёжно выдаёт оба data bytes; позицию перевести в шестнадцатые и взять по модулю 16. Иначе явно оставить отдельной последующей задачей, не делать частичную реализацию. |

При пропаже Clock нет автоматического перехода на internal BPM: sequencer
останавливается и UI показывает `Clock lost`. Точный timeout должен быть выбран
на основании максимального интервала при 40 BPM с разумным запасом и покрыт
тестами; до первого валидного `F8` статус — `Waiting`, не «идёт синхронизация».

## Архитектура

1. Проверить фактический receive API установленной версии `Adafruit_USBD_MIDI` и
   формат 4-байтных USB-MIDI event packets на RP2040. Изолировать чтение пакетов в
   Arduino-адаптере, который переводит байты в нейтральные `MidiRealtimeEvent` с
   timestamp `micros()`.
2. Создать не зависящий от Arduino `ExternalMidiClock`/`MidiClockReceiver`:
   распознаёт сообщения, считает `F8`, оценивает период с фильтрацией джиттера,
   отслеживает фазу и timeout. Для фиксированного ресурса использовать арифметику
   и малое фиксированное состояние, без allocation.
3. Разделить владение транспортом: существующий `Sequencer::update(nowUs)` не
   должен одновременно самостоятельно продвигать шаги и принимать внешние тики.
   Добавить ясный API для внешнего advance/reset/start/stop либо выделить transport
   слой. Один `F8` не обязан быть шагом; шаг продвигается только на каждом шестом
   валидном tick. Нельзя повторно сыграть шаг при коррекции фазы.
4. В `External` локальная ручка Tempo не меняет effective BPM и не может запускать
   транспорт независимо от внешнего Start/Stop. Решение по UX TempoSwitch в этом
   режиме требуется зафиксировать перед кодом: безопасное значение по умолчанию —
   поглощать короткое нажатие, при этом долгое удержание продолжает открывать
   настройки MIDI Clock.
5. Расширить UI snapshot фактическим статусом (`Waiting`, `Locked`, `Lost`) и
   отображаемым external tempo. Он может быть оценкой и не обязан менять сохранённое
   значение ручки Tempo. LVGL только отображает уже опубликованный снимок.
6. При выходе из `External` сбросить состояние приёмника и timeout; при входе —
   очистить старую фазу, начать `Waiting` и не использовать до этого внутренний
   scheduler как скрытый fallback.

## Проверки

Native-тесты должны подавать timestamped события без USB: ровные 24 PPQN, джиттер,
потеря/восстановление, Start, Stop, Continue, wraparound таймера, шесть тиков на
шаг, границу паттерна, переключения режимов и игнорирование input вне `External`.
Отдельно тестировать, что local tempo/transport не конкурируют с внешним.

На устройстве проверить DAW или hardware-master в диапазоне 40–240 BPM, Stop/Start,
Continue, краткий и долгий разрыв кабеля/потока, возврат clock и точность темпа.
Зафиксировать используемый master, прошивку и наблюдаемый результат.

## Вне объёма

MIDI Time Code, MIDI Beat Clock over DIN, автоматический выбор источника, сохранение
настроек во flash и расширенная обработка Song Position не добавляются без отдельного
решения.

## Передача результата

Заполнить после реализации: receive API/packet parsing, API приёмника и transport,
выбранный timeout/фильтр, изменённые файлы, тесты, проверка на устройстве и
отклонения.
