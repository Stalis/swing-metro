# MIDI Clock

Статус: планируется.

Этот каталог — план внедрения MIDI Clock в Swing Metro. Цель разделена на четыре
последовательных этапа, чтобы каждый из них можно было реализовать и проверить
отдельно, не смешивая UI, модель режима и MIDI-транспорт в одном изменении.

## Согласованный пользовательский сценарий

В обычном состоянии короткое нажатие ручки Tempo сохраняет текущее действие
Start/Stop. Долгое удержание этой же ручки открывает модальное окно настройки
MIDI Clock. В окне ручка Tempo выбирает режим, а её короткое нажатие подтверждает
выбор и закрывает окно.

Доступные режимы:

| Режим | Смысл |
| --- | --- |
| `Off` | Текущее поведение: MIDI Clock не передаётся и не используется как источник темпа. Значение по умолчанию. |
| `Internal` | Swing Metro остаётся ведущим по собственному tempo и посылает USB MIDI Clock. |
| `External` | Swing Metro получает USB MIDI Clock и подчиняет ему транспорт и tempo. |

Поворот вправо выбирает следующий пункт (`Off` → `Internal` → `External`),
поворот влево — предыдущий. На границах список не зацикливается. Пока выбор не
подтверждён, активный режим не меняется: UI показывает отдельно применённое и
предпросматриваемое значение. Открытие, вращение и подтверждение должны поглощать
события Tempo, чтобы не изменить tempo или транспорт по дороге.

## Нынешняя отправная точка

- `src/main.cpp` уже создаёт `Adafruit_USBD_MIDI usbMidi`, отправляет Note On/Off и
  вызывает `Sequencer::update(micros())` в основном цикле.
- `Sequencer` владеет BPM, внутренним временем шестнадцатых и Start/Stop. Сейчас
  его `toggleRunning()` вызывается по `TempoSwitch`.
- Ввод проходит через `ContextInput::Router` в `AppInputCoordinator`; сверху могут
  лежать временные контексты. Он уже умеет захватывать продолжение физического
  жеста при изменении навигации.
- UI публикуется из основного ядра через `UiViewModel`, а LVGL читает его на втором
  ядре. Из первого ядра нельзя обращаться к LVGL напрямую.
- В `docs/architecture.md` описано целевое внешнее clock-поведение. Этот план
  уточняет и реализует также ранее не включённый исходящий `Internal` режим.

## Общие ограничения

- C++17, без динамического выделения памяти в рабочем пути (`new`, `delete`,
  `std::vector`, `std::function` не добавлять).
- Модель, планировщик clock и USB-адаптер должны быть тестируемы на native-среде.
  Arduino/TinyUSB-вызовы остаются за тонким интерфейсом или адаптером.
- Модель и последовательность событий принадлежат основному ядру; LVGL получает
  только опубликованный снимок состояния.
- Нельзя менять режим или стартовать/останавливать транспорт из обработчика
  контекста: контекст только возвращает `AppEvent`, а решение применяет
  `AppInputCoordinator` после `Router::dispatch()`.
- Перед этапом 3 `Off` и `External` не должны случайно посылать MIDI real-time
  сообщения. Перед этапом 4 `External` может быть выбираемым UI-режимом, но не
  должен молча притворяться синхронизированным.

## Общая проверка

После меняющих код этапов выполнить как минимум `make format` и `make verify`.
На этапах 3–4 дополнительно проверить на настоящем устройстве USB-пакеты и
согласование с внешним MIDI-источником. Каждый документ содержит собственную
матрицу проверок.
