# Этап 1. Модель режима MIDI Clock

Статус: запланировано.

## Задача

Добавить внутреннюю доменную модель режима MIDI Clock: `Off`, `Internal`,
`External`. На этом этапе не создавать UI, не отправлять и не читать USB MIDI
Clock. Нужен единственный владелец применённого режима и небольшой API, пригодный
для будущих UI и transport-слоёв.

## Контекст

См. [README](README.md). Сейчас tempo хранится в `Counter<uint8_t>` в `main.cpp`,
а `Sequencer` владеет своим BPM и внутренним ходом. `AppInputCoordinator` является
правильной границей для применения смысловых событий после dispatch. Нельзя
прятать режим в LVGL, в `main.cpp` как несвязанную глобальную переменную или в
контексте ввода.

## Объём работы

1. Создать небольшой доменный заголовок, например `src/engine/midi_clock_mode.h`,
   с `enum class MidiClockMode : uint8_t { Off, Internal, External };`.
2. Добавить минимальный владеющий объект состояния, например `MidiClockSettings`,
   с начальным значением `Off`, типобезопасным чтением и явным применением режима.
   Он не должен знать о LVGL, `ContextInput`, TinyUSB или `Sequencer`.
3. Добавить в `AppEvent` событие применения режима, например
   `ApplyMidiClockMode { MidiClockMode mode; }`. Открытие модали и навигация по
   ней — задача следующего этапа.
4. Передать объект настроек в `AppInputCoordinator` (или в другой явно выделенный
   app-level владелец), обработать `ApplyMidiClockMode` там. Это должно быть
   единственным местом изменения применённого режима.
5. Добавить read-only доступ к применённому режиму для будущего `UiViewModel` и
   transport-слоя. Пока его можно не публиковать в UI.
6. Написать native-тесты: значение по умолчанию, применение каждого режима,
   повторное применение, корректная обработка `AppEvent` в coordinator и отсутствие
   зависимости от Arduino.

## Решения, которые уже приняты

- Значение по умолчанию строго `Off`.
- `Internal` означает будущую генерацию MIDI Clock, не изменение BPM.
- `External` означает будущий внешний источник, но на этом этапе не меняет работу
  секвенсора. Это безопасный выбранный режим, а не частичная синхронизация.
- Режим хранится в RAM. Сохранение во flash и восстановление после перезапуска не
  входят в задачу и должны быть отдельным решением.
- Названия типов могут уточняться, но должны оставаться MIDI-специфичными и не
  превращать `Sequencer` в контейнер настроек UI.

## Критерии готовности

- Проект компилируется с новым кодом, а native-тесты проходят.
- После создания приложения режим всегда `Off`.
- Явное событие меняет режим только через app-level владельца.
- Ни один код этого этапа не вызывает `usbMidi.writePacket`, не читает USB и не
  меняет timing/Start/Stop секвенсора.
- Публичные типы имеют фиксированное размещение и не требуют heap.
