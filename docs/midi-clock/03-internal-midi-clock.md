# Этап 3. Исходящий Internal MIDI Clock

Статус: запланировано. Зависит от этапов 1–2.

## Задача

В режиме `Internal` отправлять по USB MIDI стандартные real-time сообщения:
`Start` (`0xFA`), `Stop` (`0xFC`) и `Timing Clock` (`0xF8`). Источником темпа
остаётся существующий внутренний BPM Swing Metro. В `Off` и `External` этот этап
не отправляет MIDI Clock и transport real-time сообщения.

## Технический контракт

- MIDI Clock имеет 24 импульса на четверть (PPQN = 24). У текущего секвенсора
  одна шестнадцатая = четверть / 4, поэтому на один шаг приходится шесть `0xF8`.
- Период одного импульса: `60'000'000 / (BPM * 24)` микросекунд. Планировщик
  использует `uint32_t` и вычитание времени, безопасное при переполнении `micros()`.
- При переходе transport в running в `Internal` послать один `Start`, сбросить
  внутреннюю фазу clock и начать импульсы от этой точки. При остановке послать один
  `Stop` и прекратить импульсы. Повторный вызов при неизменном состоянии не шлёт
  дубликаты.
- Смена BPM пересчитывает будущий период без burst, пропусков или сдвига назад.
  Конкретную политику фазовой непрерывности зафиксировать тестами: рекомендуемый
  вариант — оставить прошлую отметку последнего импульса и применить новый период
  к следующему deadline.
- Если основной цикл опоздал, планировщик может догнать несколько просроченных
  импульсов в порядке времени, но обязан иметь фиксированный лимит на один проход,
  чтобы не зависнуть. Выбранный лимит и политика остаточного долга документируются.
- Clock не зависит от swing. Swing сдвигает ноты, но не период `0xF8`.
- На границе шага пакеты отправляются в детерминированном порядке: `Note Off`
  (если предыдущая нота активна), `Note On` (если новый шаг включён), затем
  соответствующий шестой `0xF8`. Это порядок немедленных USB-MIDI пакетов, а не
  заявление об их точной одновременности: MIDI-байты передаются последовательно.

## Архитектура реализации

1. Выделить тестируемый без-Arduino планировщик/контроллер Internal Clock (например
   `MidiClockTransmitter`). Ему передаются `nowUs`, BPM, transport transition и
   маленький интерфейс приёмника real-time сообщений.
2. `Adafruit_USBD_MIDI` оставить в `main.cpp` либо тонком USB-адаптере. Для USB MIDI
   real-time пакетов уточнить по установленному API корректный USB-MIDI event packet
   (Cable Number / CIN и байт статуса), не переиспользовать Note On/Off пакет на
   предположении. Создать отдельную функцию отправки real-time статуса.
3. Сделать один владелец переходов транспорта. Сейчас `ToggleTransport` вызывает
   `Sequencer::toggleRunning(nowUs)` в coordinator, а main loop наблюдает изменение
   и закрывает Note Off. Интеграция должна сообщать Internal Clock о том же переходе
   один раз, без двух независимых детекторов состояния.
4. Вызывать тик Internal Clock из основного `loop()` с `micros()`; не из LVGL и не
   из IRQ. Порядок `Sequencer::update()` и clock-tick выбрать и закрепить тестом,
   чтобы старт первого шага и фаза MIDI Clock были определёнными.
5. При смене режима: `Off → Internal` во время running начинает новый MIDI-сеанс
   с `Start`; `Internal → Off/External` во время running посылает один `Stop` и
   отключает генератор. Поведение применения режима реализовать через модель
   этапа 1, а не через UI.
6. Сохранить существующие Note On/Off и проверить, что добавление clock не меняет
   их channel messages.

## Проверки

Native-тесты планировщика должны покрывать 120 BPM (20 833/20 834 мкс на импульс
с выбранной целочисленной стратегией), 40 и 240 BPM, start/stop, reset фазы,
неизменный transport, переключение режимов, смену BPM, wraparound `uint32_t` и
ограниченный catch-up. Тест USB-адаптера либо compile-time проверка должны
фиксировать байты `F8`, `FA`, `FC`.

На устройстве проверить MIDI monitor/DAW: `Off` ничего не посылает; `Internal`
посылает 24 импульса на четверть и Start/Stop; tempo меняет измеряемую частоту;
секвенсор и внешнее устройство не расходятся на нескольких минутах работы.

## Вне объёма

`Continue`, Song Position Pointer, сохранение фазы при отключении и любой приём
входящих сообщений принадлежат этапу 4 или отдельной будущей задаче. Не менять
семантику `External` до его реализации.
