# Временный план этапа 1: библиотеки и плата

Основание: [architecture.md](architecture.md), этап 1, и уточнения пользователя.
Документ временный; описывает предстоящую работу, а не выполненные изменения.

## Правила согласования

- 1A выполнен и проверен сборкой и существующими native-тестами.
- 1B и 1C требуют отдельного согласования до изменения кода или конфигурации.
- Разрешение на один блок не распространяется на остальные.
- Любые переписывания и изменения вне согласованного объёма сначала обсуждаются.
- Новые проблемы сборки и поведения не исправляются молча в рамках переноса.
- После каждого блока предоставляются diff и результаты проверок.
- Создание этого документа не означает выполнение 1A или одобрение 1B/1C.

## 1A. Выделение библиотек

Статус: выполнено.

Цель: механический перенос без изменения поведения, публичного API и алгоритмов.

### Целевая структура

```text
lib/
  utils/
    library.json
    src/
      utils/
        counter.h
        counter.ipp
        round_buffer.h
        round_buffer.ipp
  ButtonMatrix/
    library.json
    src/
      button_matrix.h
      button_matrix.ipp
      button_state.h
      button_state.cpp
  Encoder/
    library.json
    src/
      encoder.h
      encoder.cpp
```

Вложенный каталог `utils` сохраняет подключения `<utils/counter.h>` и
`<utils/round_buffer.h>`. Имена файлов сохраняются в текущем snake_case.

### Работы

- [x] Перенести `Counter` и `RoundBuffer` из `src/utils/` в `lib/utils/`.
- [x] Оставить объявления шаблонных классов в `.h`, определения методов вынести
  в `.ipp`, подключаемый в конце соответствующего `.h`.
- [x] Перенести `ButtonMatrix` вместе с `ButtonState` из `src/drivers/`
  в `lib/ButtonMatrix/`.
- [x] Перенести определения шаблона из `button_matrix.cpp` в `button_matrix.ipp`;
  `ButtonState` оставить парой `.h/.cpp`.
- [x] Убрать подключение `button_matrix.instantiations.inc`: определения шаблона
  должны быть доступны без генератора и явных инстанцирований.
- [x] Перенести `Encoder` в `lib/Encoder/` как пару `.h/.cpp`.
- [x] Объявить зависимость `Encoder` от `utils`, сохранив существующее поле
  `RoundBuffer`, даже если сейчас его методы не используются.
- [x] Добавить минимальные `library.json` с фактическими зависимостями и
  ограничениями платформ; не заявлять непроверенную аппаратную совместимость.
- [x] Обновить подключения в приложении и библиотеках.
- [x] Удалить старые реализации из `src/`, не оставляя дубликатов и
  заголовков-переадресаций.
- [x] Проверить обнаружение библиотек native-окружением. Необходимые изменения
  конфигурации перечислить до внесения; посторонние исправления согласовать отдельно.
- [x] Обновить дерево и описание границы `lib/`/`src/` в `docs/architecture.md`
  с учётом явно запрошенной библиотеки `utils`.

### Ограничения

Сохраняются сигнатуры, возвращаемые типы, атрибуты, `const`, `noexcept`, значения
по умолчанию, debounce, нумерация, callbacks, выделение памяти, пины и текущая плата.
Обычные классы не переводятся в шаблоны. `.ipp` не компилируются самостоятельно.
Скрипты генерации не удаляются попутно; их очистка согласуется отдельно.

### Проверки и приёмка

- [x] Пройти существующие 9 Unity-тестов `Counter` и `RoundBuffer`:
  `pio test -e native -f test_native`.
- [x] Собрать и слинковать прошивку: `pio run -e rpipico2`.
- [x] Подтвердить отсутствие зависимости сборки от `*.instantiations.inc`.
- [x] Подтвердить отсутствие подключений файлов приложения из новых библиотек.
- [x] Проверить diff: нет изменений алгоритмов и поведения.

Проверка `ButtonMatrix<2, 3>` в двух единицах трансляции не добавлена: существующее
native-окружение не предоставляет Arduino GPIO-заглушки, а добавление отдельной
тестовой конфигурации выходит за согласованный механический перенос. Прошивка
собрана с используемым `ButtonMatrix<4, 4>`.

Сборки и тесты при подготовке плана не запускались. `pio check` не использовать
как проверку без побочных эффектов: текущая конфигурация clang-tidy содержит `--fix`.

## 1B. Исправление ввода

Статус: не согласовано, не выполнено.

Цель: устранить ошибки ввода отдельно от структурного переноса. Для каждого
исправления сначала согласуются сценарий ошибки, контракт, затрагиваемые файлы
и проверка воспроизведения.

| Проблема | Решение, требующее согласования |
| --- | --- |
| IRQ меняет состояние матрицы между чтением и подтверждением в `loop()`, событие может потеряться | Выбрать единый контекст сканирования и обработки при допустимой задержке либо синхронизированную передачу событий из IRQ с определённой политикой переполнения |
| Линейный API матрицы и лог в `main.cpp` используют разную нумерацию | Согласовать единую формулу и соответствие физическому расположению кнопок |
| `switchHandler` энкодера сохраняется, но не вызывается | Определить события нажатия/отпускания, active-low семантику, debounce и обработку в приложении |
| Невалидный переход энкодера сохраняет накопленные полушаги | Определить сброс накопления и проверить разорванную последовательность переходов |
| GUI на другом ядре напрямую читает изменяемые счётчики | Определить владельца состояния и минимальную передачу согласованного снимка |

### Работы после согласования

- [ ] Согласовать перечисленные контракты и конкретный состав исправлений.
- [ ] Реализовать доставку событий без гонки чтения и подтверждения состояния.
- [ ] Согласовать границы индексов и привести нумерацию к одному правилу.
- [ ] Подключить кнопки всех трёх энкодеров.
- [ ] Исправить обработку невалидных переходов энкодера.
- [ ] Устранить несогласованное межъядерное чтение параметров.
- [ ] Документировать debounce, допустимые контексты вызовов и потокобезопасность.
- [ ] Добавить минимальные регрессионные проверки в существующую Unity-инфраструктуру.

### Проверки и ограничения

- Проверить событие, пришедшее между опросом кнопки и подтверждением состояния.
- Проверить быстрые нажатие и отпускание между проходами основного цикла.
- Если выбрана очередь, проверить её переполнение согласно согласованному контракту.
- Проверить согласованность линейного номера и координат матрицы.
- Проверить debounce и однократную доставку согласованных событий кнопок энкодеров.
- Проверить, что разорванные последовательности энкодера не складываются в ложный шаг.
- Проверить согласованность снимка для GUI; нагрузочную проверку провести на плате.
- Не считать существующий `RoundBuffer` готовой потокобезопасной очередью.
- Не менять семантику debounce и алгоритмы утилит под видом структурной очистки.
  Обнаруженные ограничения `Counter` и `RoundBuffer` требуют отдельного решения.

## 1C. Плата и мультинажатия

Статус: не согласовано, не выполнено.

Цель: подтвердить конфигурацию Pico 2 W и безопасную работу физического ввода.

### Работы после согласования

- [ ] Подтвердить фактическую модель платы и распиновку.
- [ ] Проверить установленный board manifest `rpipico2w` и согласовать изменение

- [ ] До экспериментов с мультинажатиями проверить схему матрицы, наличие и
  направление диодов, безопасное состояние неактивных линий.
- [ ] При необходимости отдельно согласовать изменения режима сканирования
  или электрической схемы.
- [ ] Собрать прошивку для выбранной платы, проверить загрузку и USB на устройстве.
- [ ] Проверить одиночные и одновременные нажатия, удержание и отпускание.
- [ ] Проверить быстрое вращение и кнопки всех трёх энкодеров под нагрузкой GUI/Serial.
- [ ] Зафиксировать подключения, ограничения и результаты в `docs/hardware.md`.

### Аппаратные условия приёмки

Сейчас активная линия матрицы выставляется LOW, неактивные выходы держатся HIGH.
Без развязывающих диодов некоторые сочетания кнопок могут соединять выходы с
противоположными уровнями. Наличие диодов пока не подтверждено; проверка схемы
предшествует испытаниям мультинажатий.

Наличие `rpipico2w` в установленной платформе не заменяет проверку загрузки и USB.
Native-тесты и успешная сборка не заменяют испытания на железе. Wi-Fi не включается.
